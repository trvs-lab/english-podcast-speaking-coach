## 1. 总评

重写方向正确：中文入口、学习块编排、一题一个交际功能、自适应难度、纠错预算、四文件轻量状态，明显优于 v1 七文件规则系统，也不再依赖第二个 `learning-coach`。

但当前稿仍有几处**会直接复现 bad-case 体验**或**让 agent 执行摇摆**的硬伤。优先修默认用途排序、迁移频率歧义、求助/困难状态机，再补角色扮演约定与 v1 导入。

## 2. 严重问题

### 2.1 默认用途优先级写反了

`SKILL.md` 当前排序：

1. 当前请求中的明确目标  
2. `PROFILE.md` 长期目标与偏好  
3. 最近课程中的真实使用场景  
4. **课文本身最自然的交际用途**  
5. 最常见、认知负荷最低且可迁移的真实场景  

用户只说「学这一课」、档案为空时，会落到第 4 条 → 商务/禽流感类课文继续练职场会议换皮，正是 `history/bad-case/2.md` 的路径。

同文件例子却写：用户只说「学这一课」时，采用「原场景理解 + 常见真实场景迁移」。例子与优先级列表打架。

实现计划验收标准要求：无明确用途时选「最常见、低负荷、可迁移」场景；档案/历史应压过「课文默认域」。当前排序不符合该标准，也偏离体验分析中「近迁移默认去生活场景」的结论。

**建议：** 无明确当前请求时，将「常见低负荷可迁移场景」置于「课文默认域」之上；例子与优先级写成同一条规则。

### 2.2 「每轮都迁移」与「第一块只安排一次」自相矛盾

- 「每个学习块」：第一学习块内安排**一次**与主要学习用途对齐的真实迁移。  
- 「每轮教学循环」第 5 步：固定为迁移。

Agent 会二选一：

- 整块只迁一次 → 掌握证据不足；或  
- 每个表达都迁 → 课时再次被拉长。

这是执行层歧义，不是文风问题。

**建议：** 统一为例如：「每个新表达：尝试 →（需要时）纠错 → 一次目标对齐迁移；困难则再近一层简化迁移」。删除「第一块只安排一次」，或改成「第一块内至少完成一次与用途对齐的迁移」。

### 2.3 「困难」与「求助」两套计数器未对齐

| 规则位置 | 行为 |
| --- | --- |
| 自适应难度 | 第一次明显困难 → 缩短句子；连续两次困难 → 直接给完整答案 |
| 提示与答案揭示 | 第一次求助 → 关键词/短框架；第二次 → 完整答案 |

未定义：学习者说一次「给我提示」再答错，算几次困难、几次求助。容易过早摊答案，或该给关键词时直接给全文。

**建议：** 合并为一条状态机（尝试失败 / 明确求助共用同一阶梯计数）。

### 2.4 覆盖压力仍可能把课拖很长

- 核心 6–10 个「都要主动提取 + 至少一次新场景」  
- 学习者希望「尽可能掌握整篇」时，检查点后**自动进入下一学习块**

单题粒度已修好，但默认成功标准仍偏广覆盖。暂停依赖「疲惫 / 想结束」的软感知，agent 常会继续推。耗时长的根因只消解了一半。

**建议：** 明确单次会话默认块数上限或「一块一小结、默认询问是否继续」的可选节奏；「完整覆盖」作为用户明确要求时的模式，而非无条件自动连推。

## 3. 中等问题

### 3.1 角色扮演几乎没有可执行约定

`description` 触发「角色扮演」，正文几乎不写：

- 教练角色台词用英还是中；  
- 意图提示是否必须中文（防止泄露目标英文）；  
- 角色台词会暴露目标块时如何处理。

v1 中这是高频翻车点。拿掉后，开场易变成中文旁白，或英文提示中漏出答案。

**建议：** 补 2–3 行硬约定：中文意图 + 场景词；角色台词默认英文；会暴露目标块时改写/换角色/暂降为 exposure。

### 3.2 「关联」步骤容易泄题或变讲课

每轮先「用一句话说明表达的真实用途」再让人说。若用途句带出英文关键词或句型，就破坏「先提取」。

**建议：** 写死铺垫只用中文意图 + 场景词，不出现目标英文。

### 3.3 缺「无新课文」路径

旧 skill 支持：无新材料时从复习队列开复习 / 复述。当前只有「开始一节课」通读材料。用户说「复习上次」时行为未定义。

### 3.4 计划中的 v1 非破坏导入缺失

`persistence.md` 只有新四文件结构，没有 stateful-v1（`state/`、`phrase-bank/` 等）的并存导入规则。已有旧 `english-coach/` 的用户可能被当成无记录重建，或读到半套状态。

计划范围曾要求：one-time non-destructive import，不自动删除旧文件。

### 3.5 延迟提取偏软

「几轮后」「隔几个其他表达」没有下限（例如：同块内至少隔 1 个其他表达再抽）。`evaluation.md` 查得细，但热路径 agent 不读它，课中容易漏做。

**建议：** 在 `SKILL.md` 热路径写一条可执行的最小间隔规则。

## 4. 较轻问题

- `description` 未排除「单独练发音」；计划草稿 description 曾包含该边界。  
- `evaluation.md` 场景 4 复述了错误优先级（课文用途在低负荷场景之前），会把错误验收固化。  
- `PHRASES.md` / `REVIEW.md` 以表达做标题，缺「同一框架不同槽位如何合并」的一句话，短语库易膨胀。  
- 若 `README.md` 仍描述七文件 + ledger，会与现 skill 脱节（文档债，非 skill 正文问题）。

## 6. 建议修复优先级

1. **改默认用途排序**：无明确请求时，「常见低负荷可迁移场景」压过「课文默认域」；例子与优先级一致。  
2. **统一迁移频率**：删掉或改写「第一块只安排一次」与「每轮循环第 5 步迁移」的冲突。  
3. **合并求助 / 困难阶梯**为一条状态机，并补角色扮演语言约定。  
4. 随后：无新课文复习路径、v1 非破坏导入、延迟提取最小间隔、evaluation 场景 4 与优先级对齐。

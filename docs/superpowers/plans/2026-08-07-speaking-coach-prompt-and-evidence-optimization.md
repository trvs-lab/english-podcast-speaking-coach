# English Podcast Speaking Coach 提示与证据优化计划

日期：2026-08-07

## 目标

让课堂始终围绕一个判断推进：

> 当前最值得练的关键表达，还缺哪一档证据？

课程长度、提示强度、是否更换情境、是否安排整合，都由课文内容和学习者当前表现决定。本轮重点修复以下问题：

1. 场景词可能与目标回答无关、冲突或产生误导；
2. 教练造成的提示错误被归因给学习者；
3. 同一问题再次出现后，没有定位根因并完成验证；
4. 跨课待复习项目被读取后又悄然丢失；
5. 反馈检查了英语自然度，却没有先检查回答是否完成中文意图；
6. `REVIEW.md` 条目混合多个需要分别验证的问题。

本轮不扩展听力、发音、语调、跟读、录音或音频处理能力。

## 设计原则

### 1. 按证据缺口推进

课堂不按开口次数推进，也不按固定流程模板推进。每轮只处理当前最有价值的证据缺口：首次尝试、修复、撤除帮助后的再次提取，或尚未覆盖的关键表达。

### 2. 场景服务于表达

场景用于帮助理解、触发表达和验证使用能力。场景不承担数量指标，不要求每课或每个学习块完成固定次数的迁移。

需要把表达写入「已经能自己说出来」时，仍须取得自然、无提示、非同构情境中的独立使用证据。没有合适的新情境时，不强行迁移，也不虚报掌握。

### 3. 局部调整，不推断全局能力

某两个表达连续答对，只能影响这些已证明表达的反馈密度和重复次数，不能推断后续新表达适合自由输出。

新的核心表达仍可从明确情境和中文意图开始。只有任务主要由已经练过的表达组成时，才考虑意图式回应、角色回应或整合。

### 4. 教练对题面负责

场景词、翻译、人物信息或任务约束存在错误时，先修正题面，再评价学习者。教练造成的错误不能成为学习者的复习债务。

### 5. 每个长期条目只表达一个判断

`REVIEW.md` 中的每个条目都应能由一道聚焦题目单独验证。表达提取、搭配、词形和交际意图判断需要不同题目时，应分别记录。

## 不采用的控制方式

本轮不引入以下规则：

- 不设置固定开口次数或硬性上下限；
- 不因连续两次成功而全局进入快车道；
- 不强制成功后的下一题升级为自由表达；
- 不固定每个学习块包含多少表达；
- 不规定每课或每块必须迁移多少次；
- 不为了跨课复习，把旧表达硬塞进不自然的场景。

开口次数和迁移次数可以作为观察数据保留，但不作为通过条件。

## 自适应教学模型

开课前通读完整材料，根据交际价值、复用价值和学习目标确定关键表达，不为满足数量范围而凑候选。每个关键表达在内部处于以下状态之一：

| 当前证据 | 下一步 |
| --- | --- |
| 尚未尝试 | 给适合该表达的首次提取 |
| 原场景独立说出 | 记为覆盖；按表达价值决定是否继续验证 |
| 说错或没说出 | 最小纠正，随后在相近场景重试 |
| 借助关键词或示范完成 | 记为辅助完成，之后在自然时机撤除帮助再试 |
| 合适的新情境中独立使用 | 证据充分，不再专门重复 |
| 再次出现同类问题 | 定位根因，讲一个判别点，再回到口语任务验证 |
| 本课无法完成独立验证 | 保留为待练，不以集中重复冒充掌握 |

课程满足以下条件时可以结束：

> 核心表达都已获得与本课表现相符的诚实归宿，并且当前没有仍需立即完成的修复。

学习者主动暂停、负担持续上升，或者继续集中重复已经没有价值时，将尚未验证的缺口留给间隔复习。

## 实施计划

### 阶段一：更新评估合同

先修改 `evaluation.md`，防止运行规则调整后仍被旧的代理指标判错。

#### 修改内容

删除或降级以下硬指标：

- 有效开口不得超过 22 次；
- 连续两次正确后必须进入快车道；
- 至少三个核心表达必须完成生活迁移；
- 使用迁移次数判断课堂质量。

替换为以下判断：

- 每个 `active` 条目都有合格的新情境无提示证据；
- 没有合适新情境时，不强行迁移、不虚报 `active`；
- 已证明会用的表达没有无价值的连续同构重复；
- 每个核心表达都有可定位的课堂结果；
- 场景选择首先保证目标表达自然适用。

将以下记录加入固定历史样本：

- `history/test/080501.md`：检查关键表达选择、纠错后的状态判断和 `REVIEW.md` 粒度；
- `history/test/080601.md`：检查跨课复习、中文意图一致性和自然答案接纳；
- `history/test/080701.md`：检查场景词误导、提示污染、重复问题修复和复习条目拆分。

#### 完成标准

- 评估关注证据质量，不再以轮数、任务形态和迁移数量代替学习结果；
- 三份最新测试均有明确的保护行为和失败行为；
- 历史测试记录保持只读。

### 阶段二：建立提示完整性检查

修改 `skills/english-podcast-speaking-coach/SKILL.md` 中的场景词和出题规则。

#### 重定义场景词

建议使用以下规则：

> 场景词只提供完成目标回答确实需要、且学习者大概率不会的内容词或短语，不限词性。场景词不是对场景中所有事物的注释；不能只是情境里出现的对照项，不能与中文意图冲突，也不能泄露本轮要练的表达。多数题目不需要场景词。

#### 发题前检查

生成题面前在内部确认：

1. 目标表达在当前场景中是否自然，而不是勉强可用；
2. 中文意图、目标答案和人物信息是否一致；
3. 每个场景词是否确实服务于目标回答；
4. 场景词是否会诱导出与目标相反的答案；
5. 是否存在同样清楚但不需要场景词的题面。

针对 080701 的「电梯坏了，走楼梯」：

- `电梯 elevator` 只是背景中的对照项，应删除；
- 如果判断 `stairs` 会阻塞表达，可以提供 `楼梯 stairs`；
- 如果 `stairs` 本身是本轮评估点，则不提供英文提示。

#### 完成标准

- 误导性、无关性和对照性场景词为零；
- 每个保留的场景词都能说明它在目标回答中的具体用途；
- 目标表达在所选场景中是自然选择。

### 阶段三：处理提示污染

在 `SKILL.md` 的「援助与查漏」中增加提示污染规则。

#### 建议规则

> 如果题面的场景词、翻译、人物信息或约束错误、矛盾或具有明显诱导性，教练先明确更正并承担责任。受污染部分不计为学习者失败，不进入 `REVIEW.md`；不受污染的正确结构可以照常认可。随后用无污染的相近题面重新验证。

080701 中应执行以下处理：

- 认可 `That's all right` 和 `Let's take...` 的正确结构；
- 明确说明场景词给错；
- 不使用「把交通方式说反了」等归责表述；
- 不把该轮作为 `take the stairs` 提取失败的证据；
- 使用干净的新题面重新尝试。

同步修改持久化规则：

- 被提示污染的错误不得写入 `REVIEW.md`；
- 错误提供的场景词不得进入课末词表；
- 只有后续干净重试可以决定表达状态。

#### 完成标准

- 教练诱导的错误被归因给学习者的数量为零；
- 受污染的回答不会改变长期学习状态；
- 更正后的题目能够重新产生有效证据。

### 阶段四：统一反馈顺序并修复重复问题

这一阶段合并「重复问题根因修复」和「中文意图一致性」两项改进。

#### 反馈检查顺序

反馈前依次判断：

1. 是否完成题目的交际意图；
2. 人物、时间、数量和肯否关系是否与题面一致；
3. 核心表达是否正确；
4. 表达是否自然；
5. 是否只有次要书写问题。

例如，080601 指定「她一家人」，回答使用 `his family` 时，应指出人物信息发生变化。其他自然、正确的结构仍先认可，不把内容偏差扩大成无关的语法讲解。

#### 同一问题第二次出现

只有同一个语言判断再次出现时才启动根因修复，例如：

- `chill` 和 `chilly`；
- `financial` 和 `financially`；
- `Let me...` 和 `I'll...`。

处理顺序：

1. 确认这是同一问题再次出现；
2. 使用一个判别性问题或最小对比例定位混淆；
3. 只讲一个决定性区别；
4. 返回新的口语场景验证；
5. 验证后再决定是否进入 `REVIEW.md`。

纯大小写、标点、空格和撇号等表面问题不触发根因修复。

#### 完成标准

- 第二次出现的同类问题都有一次根因定位；
- 定位后都有口语验证，或在课末明确标记为尚未验证；
- 改变题意的人物、时间、数量和肯否偏差不会被反馈遗漏；
- 正确部分仍得到具体认可。

### 阶段五：保持 `REVIEW.md` 条目原子化

修改 `skills/english-podcast-speaking-coach/references/persistence.md`。

#### 条目原则

> 一个 `REVIEW.md` 条目只记录一个以后能够被单独复现和验证的语言缺口。

080701 不应把以下两个问题合成一个条目：

- `take the stairs`：表达是否能够无提示提取；
- `Let me... / I'll...`：请求许可和表达个人决定的区别。

只有两个问题需要不同题目才能验证时才拆开。同一固定搭配内部不可分割的问题仍保留为一个条目，避免为了原子化机械拆分。

每个条目必须能够回答：

- 当前缺少什么；
- 下次使用什么情境验证；
- 什么表现代表问题已经修复。

#### 完成标准

- 任取一条 `REVIEW.md` 记录，都能设计一道只验证该问题的题目；
- 表达提取问题和一般语言判断不会含糊地混在同一条记录中；
- 提示污染产生的问题不会进入记录。

### 阶段六：补全跨课复习的处理结果

启动读取 `REVIEW.md` 后，对本次到期的高优先级 `repaired` 项进行轻量决策：

- 与当前课文自然相容：选择最多一两个穿插；
- 与当前课文不自然相容：不强行加入；
- 当前课程负担较高：保留到后续课程。

课末核对本次到期的高优先级项目：

- 已复习：记录新证据；
- 未复习：继续保留，并记录更适合复习的课程类型；
- 不再需要复习：必须有新的证据支持移除。

用户可见小结不必逐条解释所有延期项目，可以合并说明。例如：

> 上节课的任职和日期表达与本课场景不太相容，继续留到更合适的课程复习。

重点是防止旧内容在读取后无声消失，不要求每节新课都复习旧内容。

#### 完成标准

- 本课启动时到期的 `repaired` 项，课末都能归入「已复习」或「明确保留」之一；
- 跨课项目不会为了完成规则被塞入不自然的场景；
- 未复习项目仍保留有效的下一次复习入口。

## 回归测试

### 080701：场景词与重复错误

固定检查：

- 「电梯坏了，走楼梯」题面不得提供 `elevator`；
- 如果使用旧版错误题面，教练必须主动承担提示错误；
- 受污染答案不得进入 `REVIEW.md`；
- `chill/chilly` 第二次出现后必须完成最小诊断和完整口语验证；
- `take the stairs` 与 `Let me... / I'll...` 不得混成一个无法单独验证的条目。

### 080601：意图一致性与跨课复习

固定检查：

- 中文指定「她一家人」，回答使用 `his family` 时必须识别意义偏差；
- 自然表达的正确部分仍先认可；
- 从 080501 继承的 `have trouble doing`、`put something off` 等项目必须有明确去向；
- 未穿插的到期项目继续保留，不强行塞进签证场景。

### 080501：复习记录粒度

固定检查：

- `extension` 的冠词、介词和直接请求方式只在需要不同验证时拆分；
- `put off` 的表达提取和时间介词问题不被含糊地合成一个宽泛债务；
- 即时修复不能冒充独立掌握。

## 最终验收标准

本轮优化完成后应满足：

- 场景词都与目标回答直接相关；
- 教练造成的提示错误不计为学习者错误；
- 中文意图中的人物、时间、数量和肯否关系不会被反馈忽略；
- 同一语言问题第二次出现后有根因修复和口语验证；
- 每条 `REVIEW.md` 记录只包含一个可单独复现的问题；
- 到期的跨课 `repaired` 项不会无声消失；
- `active` 状态都有真实证据；
- 课程长度由关键表达和学习者表现决定；
- 没有固定开口次数、全局快车道或迁移次数要求；
- 没有为了满足流程而制造不自然场景。
